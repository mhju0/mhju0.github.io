FullCourt

FullCourt calculates rest and travel between NBA games and compares win rates by rest condition against the home-team win rate. Results can also be split by rest gap and era.

How did I check that the stored games are right?

An audit of the full history found 783 missing overtime records, which I filled from primary sources. I then checked the 5,815 games still unconfirmed against NBA box scores, corrected 346 more, and recomputed the figures.

Highlights

  • Game updates run in a transaction with row locks
  • 783 missing overtime records filled from primary sources
  • Lock order fixed by game ID to prevent deadlocks
  • Transaction tests run on real PostgreSQL in CI

How it works

  1. Schedule collection

    A scheduled job fetches game schedules and results every day. The trigger request is verified by comparing a secret token in constant time.

  2. Rest · Travel

    Rest days per team and travel distance between cities are calculated from the schedule, and team schedules are linked to game details.

  3. Storage

    Updating a game locks its row inside a READ COMMITTED transaction. When several rows are locked, they are locked in game-ID order so that no deadlock can occur.

  4. Pages

    Responses for past seasons are cached on the CDN for an hour, and in-season responses for 60 seconds. Request values are validated with Zod schemas, and invalid ones get a 400.

Rest indicators do not guarantee wins, and historical associations are not causal effects of rest.
